# SwingPulse Dashboard — App Documentation

## Overview

SwingPulse is a single-page trading dashboard that visualizes signal data generated by the SwingPulse Signal Generator. It displays 220 financial instruments with their MA ribbon signals, trend states, key levels, volume analysis, signal confidence scoring, multi-timeframe alignment, ribbon compression alerts, and momentum indicators across four timeframes: **4-Hour, Daily, Weekly, and Monthly**.

**Live:** https://swingpulse.pages.dev
**Local dev:** `python3 swing_generator/webapp/server.py` → http://localhost:5050

---

## Architecture

```
webapp/
├── server.py              Flask dev server (API endpoints)
├── publish.py             Static site builder + Cloudflare Pages deploy
├── templates/
│   └── index.html         Single-page HTML shell (5 tab panes)
├── static/
│   ├── css/style.css      Full theme system (dark/light), all component styles
│   └── js/app.js          All client-side logic (IIFE, ~1050 lines)
└── publish/               Generated static site (gitignored)
    ├── index.html
    ├── static/             CSS + JS (with API URLs rewritten to static paths)
    └── data/               JSON files (signals, summary, tv-map, trends, history/)
```

### Two Hosting Modes

| Mode | Server | Data Source | Use Case |
|------|--------|-------------|----------|
| **Flask Dev** | `server.py` on port 5050 | Live API endpoints (`/api/*`) | Local development, testing |
| **Static (Cloudflare)** | Cloudflare Pages CDN | Pre-built JSON files (`data/*.json`) | Production dashboard |

`publish.py` bridges the two by copying the app and rewriting `fetch('/api/signals')` → `fetch('data/signals.json')`, etc.

## Tabs

The app has 5 tabs, navigated via a bottom navigation bar (mobile-friendly):

### 1. Dashboard

The main overview with:

- **Market Pulse Banner** — Sentiment indicator (Bullish / Bearish / Mixed) based on the ratio of uptrend to downtrend instruments. Bullish when uptrends > 1.5x downtrends. Color-coded pulse rings animate the banner.

- **Summary Stat Cards** — Four clickable cards showing counts for Buy Signals, Sell Signals, On Watch, and Volume Spikes. Each has an animated counter and progress bar. Clicking a card filters the heatmap below to show only that category.

- **Charts Row** — Three Chart.js charts:
  - *Trend Distribution* — Doughnut chart (uptrend / downtrend / neutral)
  - *Signal Breakdown* — Bar chart (P1 / P2 / P3 / P4 counts)
  - *Signals by Sector* — Horizontal stacked bar (buy / sell / neutral per group)

- **Market Heatmap** — Grid of all instruments color-coded by signal state (green=buy, red=sell, grey=neutral, amber=watch). Group filter buttons above. Each cell shows the instrument name and signal type. Hover reveals TradingView link and detail button.

- **Timeframe Alignment Summary** — Grid showing how many instruments fall into each alignment category (Triple Bull, Aligned Bull, Leaning Bull, Mixed, Counter-trend, Leaning Bear, Aligned Bear, Triple Bear). Color-coded by direction.

- **Ribbon Compression Alerts** — List of instruments where `ribbon_compression === 'yes'` (MA spread < 2%). Each row shows spread %, MA order score, and directional lean. Indicates a "squeeze" — MAs converging before a potential big move.

- **Active Signals Feed** — List of instruments with active primary or secondary signals, sorted by priority (P1 first). Each row shows signal badge, confidence level (high/standard/low), timeframe alignment badge, confirmation status, and TradingView link.

### 2. Signals

Full signal list with filtering and sorting:

- **Search** — Text filter by instrument name, group, or sector
- **Trend Filter** — Dropdown: All Trends / Uptrend / Downtrend / Neutral (filters by `established_trend`)
- **Sort** — Dropdown: Default / % Move descending / % Move ascending (sorts by `pctFromMa()` — percentage distance from the longest MA)
- **Signal Type Chips** — All / Buy / Sell / P1 / P2 / P3 / P4 / Secondary

Each row shows: instrument name, confirmation status, signal badge, confidence badge (high/standard/low), timeframe alignment badge, established trend, % from MA 150, current price, ROC momentum, squeeze indicator, and last signal date. Rows are clickable to open the detail modal.

### 3. Scanner

Card-based instrument browser with:

- **Search + Group Filter + Trend Filter** — Three independent filters
- **Instrument Cards** — Each card shows:
  - Signal strip (BUY P1 (HIGH), SELL P2, etc.) at top if active — includes confidence level
  - Instrument name, group/sector
  - Current price with ROC momentum indicator
  - Tags: trend direction, timeframe alignment, squeeze alert, volume spike, key level touch, trend run days
  - MA Order gauge bar (0-16 scale showing how many MA pairs are in correct order)
  - Mini progress bar showing trend duration (scaled to 100 days)

### 4. Watchlist

Four watchlist categories displayed as card grids:

| Card | Data Source | Shows |
|------|------------|-------|
| **Potential Turning Points** | `potential_turning_point_flag` | Instruments with trends > 200 days |
| **Watch Flags** | `watch_flag` | Price approaching the MA ribbon edge (within 1.5%) |
| **Key Level Touches** | `key_level_touched_today` | Price at a historical support/resistance level (daily only) |
| **Volume Spikes** | `volume_spike_flag` | Today's volume > 2x the 25-day average |

### 5. Trends

Split-panel trend history viewer:

- **Left sidebar** — Searchable list of all instruments with colored dot (green/red/grey) showing current established trend
- **Right panel** — Selected instrument's trend history:
  - Summary stats: total trends, up/downtrend counts, longest up/down, average durations
  - Trend timeline: visual bars for each segment showing direction, duration (days), % price move, and date range. Most recent segment marked "(current)"

Data comes from `trends_YYYY-MM-DD.json` generated by `main.py`.

## Timeframe Toggle

The **4H / D / W / M** toggle in the top bar switches all tabs to use data from the selected timeframe. The active timeframe is persisted in `localStorage`.

### How It Works

The `f(field)` function maps field names to the correct column prefix:

| Timeframe | Prefix | Example |
|-----------|--------|---------|
| 4H | `h4_` | `h4_close`, `h4_trend_direction`, `h4_primary_signal` |
| D (Daily) | *(none)* | `close`, `trend_direction`, `primary_signal` |
| W (Weekly) | `w_` | `w_close`, `w_trend_direction`, `w_primary_signal` |
| M (Monthly) | `m_` | `m_close`, `m_trend_direction`, `m_primary_signal` |

When the timeframe changes, `renderAll()` re-renders every tab using the new prefix. The Daily summary comes from the server; for other timeframes, `computeSummary()` recomputes stats client-side from the prefixed fields in `allData`.

## Instrument Detail Modal

Clicking any instrument opens a full detail modal with:

1. **TradingView Hero Card** — Large clickable card linking to TradingView with the instrument's chart. Shows name, group, price, and active signal badge.

2. **Quick Stats Grid** — Trend direction, run days, MA position (% above), TF alignment badge, MA order score (0-16), momentum (ROC %), open, high, low.

3. **MA Ribbon Gauge** — Visual progress bar showing what percentage of the 17 MAs the price is above (green when >70%, red when <30%, amber otherwise). Displays ribbon spread % and squeeze indicator if compression detected.

4. **Signal Status** — Current confirmation status with confidence badge (high/standard/low), last signal details (type, date, days ago), and volume spike note on signal bars.

5. **TradingView Embedded Chart** — Live iframe widget from TradingView showing the instrument's chart at the selected timeframe interval.

6. **MA Ribbon Analysis Chart** — Chart.js line chart showing 250 periods of close price with MA 38, MA 80, and MA 150 overlaid. Data fetched from `/api/history/{name}`.

7. **MA Values** — Pill badges for all 17 MA values, color-coded green (price above) or red (price below).

8. **Volume** — Current period volume vs average, with spike indicator.

9. **Key Levels** — Table of up to 15 support/resistance levels showing type (top/bottom), price, touch count, and date.

## TradingView Integration

Every instrument links to TradingView with the correct exchange prefix and timeframe interval.

### Symbol Mapping

`server.py` builds a `display_name → EXCHANGE:SYMBOL` map with these priorities:

1. **Explicit overrides** (`_TV_BY_NAME` dict) — Commodities (TVC:GOLD), indices (CAPITALCOM:US100), crypto (COINBASE:BTCUSD, BINANCE:XRPUSDT), NYSE stocks (NYSE:AAPL), NASDAQ stocks, etc.
2. **German stocks** (.DE tickers) → `XETR:symbol`
3. **Forex** (=X tickers) → `FX:symbol`
4. **Fallback** — Raw name (TradingView auto-resolves)

### Timeframe Intervals

| Dashboard TF | TradingView URL param | Widget interval |
|-------------|----------------------|-----------------|
| 4H | `&interval=240` | `240` |
| D | *(default)* | `D` |
| W | `&interval=W` | `W` |
| M | `&interval=M` | `M` |

### Link Types

- `tvBtn()` — Small icon link (used in heatmap cells, signal rows, watchlist items)
- `tvBtnFull()` — Full button with "Open on TradingView" label
- `tvWidgetUrl()` — Embedded iframe widget URL (used in modal chart preview)

## Data Flow

### Flask Dev Server

```
Browser loads index.html
  → JS fires loadAll()
  → Parallel fetches:
      /api/signals   → allData[] (220 instrument rows, 96+ columns each)
      /api/summary   → summaryData{} (pre-computed stats for daily)
      /api/tv-map    → tvMap{} (instrument → TradingView symbol)
      /api/trends    → trendsData{} (trend segments per instrument)
  → renderAll() updates all 5 tabs
```

On modal open: `/api/history/{name}` returns 250 days of OHLCV + MA values for the chart.

### Static Site (Production)

`publish.py` pre-generates all API responses as JSON files:

```
publish/data/
├── signals.json         All instrument data
├── summary.json         Dashboard summary stats
├── tv-map.json          TradingView symbol map
├── trends.json          Trend segment history
└── history/
    ├── GOLD.json        Per-instrument chart data (250 bars + MAs)
    ├── AAPL.json
    └── ... (one per instrument)
```

The JS `fetch()` calls are rewritten to point at these static paths. The refresh button triggers `window.location.reload()` instead of clearing the server cache.

## Server API Reference

| Endpoint | Method | Response | Notes |
|----------|--------|----------|-------|
| `/` | GET | HTML | Renders `index.html` |
| `/api/signals` | GET | `{date, data: [...]}` | Full signal data for all instruments |
| `/api/summary` | GET | `{date, total, trend_counts, buy_count, ...}` | Pre-computed daily summary |
| `/api/tv-map` | GET | `{name: "EXCHANGE:SYM", ...}` | TradingView symbol mapping |
| `/api/trends` | GET | `{name: [{direction, start, end, days, pct_move}]}` | Trend segment history |
| `/api/history/<name>` | GET | `{ticker, data: [{date, open, high, low, close, volume, ma_38...}]}` | 250-period OHLCV + MAs |
| `/api/ticker-map` | GET | `{name: "yahoo_ticker", ...}` | Display name → Yahoo ticker |
| `/api/refresh` | POST | `{status: "ok"}` | Clears data cache |

## Static Deployment (publish.py)

### Build Process

```bash
python3 swing_generator/webapp/publish.py              # Build + deploy
python3 swing_generator/webapp/publish.py --build-only  # Build only
```

Steps:
1. Creates `publish/` directory with `data/` and `data/history/` subdirectories
2. Copies `static/` assets (CSS, JS, icons)
3. Loads latest `signals_YYYY-MM-DD.csv` from `output/`
4. Generates JSON: `signals.json`, `summary.json`, `tv-map.json`, `trends.json`
5. Generates per-instrument history JSONs (250 bars each with MAs computed on the fly)
6. Copies `index.html` from templates
7. Rewrites `app.js` fetch URLs from `/api/*` to `data/*.json`
8. Deploys to Cloudflare Pages via `npx wrangler pages deploy`

### Cloudflare Pages Config

- **Project name:** `swingpulse`
- **Branch:** `main`
- **Live URL:** https://swingpulse.pages.dev

## Key JavaScript Functions

| Function | Purpose |
|----------|---------|
| `f(field)` | Returns timeframe-prefixed field name (`h4_close`, `w_close`, etc.) |
| `computeSummary()` | Recomputes summary stats for non-daily timeframes from `allData` |
| `pctFromMa(item)` | Calculates % distance from longest MA (ma_150) — used for sorting |
| `renderAll()` | Re-renders all 5 tabs (called on timeframe change and data load) |
| `renderDashboard()` | Updates pulse banner, stat cards, charts, heatmap, signal feed |
| `renderSignals()` | Builds filtered/sorted signal list with % move display |
| `buildScannerCards()` | Builds scanner card grid with filters |
| `renderWatchlist()` | Populates 4 watchlist categories |
| `renderTrendsInstrumentList()` | Builds searchable instrument sidebar for trends |
| `renderTrendDetail(name)` | Renders trend timeline with stats for selected instrument |
| `openModal(name)` | Opens full instrument detail modal with TradingView integration |
| `loadModalChart(item)` | Fetches history and renders Chart.js MA ribbon chart in modal |
| `tvUrl(name)` | Generates TradingView chart URL with correct exchange and interval |
| `tvWidgetUrl(name)` | Generates TradingView embedded widget iframe URL |
| `rebuildCharts()` | Destroys and recreates all Chart.js charts (called on theme change) |
| `buildHeatmapCells()` | Renders heatmap grid with group and stat card filters applied |
| `renderAlignmentSummary()` | Renders TF alignment category counts on dashboard |
| `renderCompressionFeed()` | Renders ribbon compression (squeeze) alerts on dashboard |
| `alignCls(label)` | Returns CSS class for an alignment label (align-bull/bear/mixed/counter) |
| `isBuy(item)` / `isSell(item)` | Checks `confirmation_status` for buy/sell keywords |
| `formatPrice(val)` | Formats price with appropriate decimal places |
| `animateCount(el, target)` | Animates stat card numbers from current to target value |

## Adding Features

### Adding a New Tab

1. Add a `<section class="tab-pane" id="pane-newtab">` in `index.html`
2. Add a `<button class="nav-tab" data-tab="newtab">` to the bottom nav
3. Add a `renderNewTab()` function in `app.js`
4. Call it from `renderAll()`

### Adding a New Timeframe

1. Add the button in the `tf-toggle` div in `index.html`
2. Add the prefix mapping in `f()` in `app.js`
3. Add the TradingView interval in `tvUrl()` and `tvWidgetUrl()`
4. Ensure the backend outputs the prefixed columns (see backend DOCUMENTATION.md)

### Adding a New Signal Filter

1. Add a `<button class="chip" data-filter="newtype">` in the signal filter chips
2. Add the filter logic in `renderSignals()` where `activeSignalFilter` is checked
